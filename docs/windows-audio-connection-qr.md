# Audio reception connection QR

Device Discovery's existing audio reception panel shows a LAN QR after reception starts. The phone or tablet can consume the same `skybridge://lan/v1` hint as copy/paste. Copy remains available in the command bar's overflow menu. The QR contains only the public endpoint, device ID, protocol-key fingerprint and name; scanning does not grant pairing approval or account authority. Both endpoints must still be reachable.

Publication captures the exact MAIN listener, account lifetime, identity and selected interface. The interface ID, index and address are checked against current native enumeration. Image decoding remains owned until it completes, then publication is rechecked before display. The existing UI timer coalesces network events, clears stale pixels and permits one refresh per network revision; an explicit retry handles a failed render. Stopping reception or retiring the account clears the QR. Errors are visible and do not substitute another address or relax authentication.

QRCoder 1.8.0 renders the complete UTF-8 payload with error correction M and a four-module white quiet zone. The 21 deterministic vectors cover ASCII, Chinese, supplementary Unicode and mixed maximum-length names. The contract executable can export them to a new directory with `--export-lan-qr <directory>`. `Scripts/verify-windows-lan-qr-images.ps1` checks their hashes, bounds, quiet zones and exact decoded payloads using the SHA-256-pinned ZXing 3.5.4 artifact used by Android.

Two generated images exposed a single-candidate finder failure in the earlier Android decoder. Changing QR encoding mode alone did not fix both. The Android repository independently fixes its bounded multi-candidate detector and retains both regression images; phones need that repair for the full corpus. No wire-format or trust-policy change is involved.

Local validation on 2026-10-18: the contract project built with zero warnings/errors; 17 LAN publication/QR cases passed. All 21 generated images decoded exactly with the updated bounded ZXing detector and native Apple Vision. Android's physical-device test decoded 22 fixed images, including the earlier mixed-mode counterexample. Workflow syntax, PowerShell syntax and FFI checks passed. Native Windows build and interactive checks run separately in `Windows Portability`; dispatch with `run_ui_smoke=true` to attempt the existing window/UI Automation gate. These image and component results do not prove a rendered Windows QR, a physical camera scan, live pairing, exclusive output or audible playback.

Local diagnostic receipts, including failed earlier single-detector attempts, are preserved under `artifacts/audio-qr-20261018/`. The separate native baseline had passed product build and 718 contract checks, but the complete portability workflow remained failed because its online .NET runtime freshness check found a newer runtime. That gate is retained without weakening it.
